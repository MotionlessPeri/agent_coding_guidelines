# Lane 拓扑设计:怎么切、什么时候重切

> 来源:一次真实的拓扑重划(2026-08-31,mocap 项目:8 条按「技术子域 + 职能」混切的 lane
> → 3 仓 6 lane 按「仓库 + 三权」切),以及重划后一周的运行实测。**单项目一次,用户主导促升**
> ——切法规则已被新拓扑的日常运行验证,重划本身的执行经验只跑过一遍,apply-and-refine。
> 本文管**拓扑怎么设计**;lane 间日常协调(唤醒 / brief / 收件箱 / 轮换)在
> `skills/collaboration/role-lane-coordination`,同 repo 多会话的 hook 底层在
> `multi-session-coordination`,两处不复述。

## 核心规则(六条)

1. **lane 边界跟仓库边界对齐,不跟技术子域对齐。** 每个独立 repo(含 submodule 升独立仓的)
   一条 lane,拥有整仓 + 对外口。
2. **职能三权分立,每条 lane 写明「不做」清单**:协调(派单 / 版本钉定 / 对外出口,**不实现**)/
   实现(**一条** lane 吃下一个仓的全部代码)/ 裁决(设计 + 正确性审,**零文件所有权**)。
3. **审查不常驻**:正确性审并入裁决 lane;大型审计按 **campaign 制**临时开 lane,审完归档。
   审查是波动负载,常驻一条 lane 的成本换不来它空转期的价值。
4. **接缝要有名有主**:两条 lane 边界相交的每个契约面,登记「缝 / owner / 协调规则」成表;
   **触发挂 git 可观察事件不挂人**(版本钉定前进 / 目录搬迁 / 合并上游 ⇒ 派对应复核)。
5. **role description 只写归属与边界**;会变的数字 / 命令 / 读数走 durable 文档指针 ——
   role 不会因过期变红,写进去的每个数都是给下一代埋的假话。
6. **lane 数量即成本**:每条 lane 是一个独立模型会话(multi-agent ≈ 15× 单 chat,见
   `techniques/coordination-patterns.md` 成本节)。**加 lane / 并行派活前先给用户一行报价**,
   强度档(范围 / 复核深度 / 并行度)由用户选。

## 旧拓扑的问题(实测账,不是推演)

旧形态:`hub / arch / render / ui / review / hotfix / design(+ 实现散在各技术域 lane)`——
render、ui 按**技术子域**切,arch / review / hotfix 按**职能**切,混在一张表里。

| # | 问题 | 实测证据 |
|---|---|---|
| 1 | **域切分跟仓库边界不重合**。代码持续下沉进共享库后,「render 域」的文件一半住在别人仓里 ⇒ owner 与仓错位,一次改动的 push → 版本钉定链穿过 2–3 条 lane | 出仓期 626 刀中 13 刀跨 lane 边界,其中 11 刀是搬迁形态 —— 边界本身在制造协调 |
| 2 | **缝无主**:两条 lane 都会碰的契约面(共享容器、双向信号、同名异义函数)没人认领 | 一周内**四次互抓错全发生在缝上**;`set_undo_stack` 同名两义还归错过一次对象 |
| 3 | **审查常驻空转**:review lane 的负载是 campaign 型(一场审计满负荷,平时零) | 并入裁决 lane 后无损失;后续大审计临时开 lane 归档即可 |
| 4 | **职能 lane 的存在前提会静默消失**:hotfix 独立 lane 的前提是「生产分支需要隔离树」,分支模型一变前提归零,lane 却还在 | 「值守流量低」不可作裁撤论据(那是结构性下界);真论据是**隔离前提已不存在** |
| 5 | **实现权分散 = 共享树写冲突面大**:多条 lane 同时写一个仓,共享 git 索引互吞、同文件 hunk 混提交、全量读数被别人中途态污染 | 各有实测事故(索引差 3 秒吞 4 文件 / 「只 docstring」的 commit 带走别人的重构 / 207 假红) |
| 6 | **复核靠人记得** ⇒ 版本钉定前进、目录搬迁之后的连带检查会漏 | 层表登记欠账攒到 17 个模块才被撞见 |

## 新拓扑的形状与痛点映射

```
<共享库A>/hub   库整仓 + 对外口(push 通知 → 主项目收 pin;breaking change 预告双下游)
<共享库B>/hub   同上(嵌套第三方依赖的版本钉定也归它)
<主项目>/hub    纯协调:需求池 / 派单验收 / 三层版本钉定 / 对外出口 / 事件触发表执行人
<主项目>/app    全部实现 + 生产值守(值守优先级 > 开发线,用户可改)
<主项目>/design 设计裁决 + 正确性审,零文件所有权;领域中性门的判官(门在库仓、判官在库外)
(退役)         arch → 并入 hub;render/ui → 按仓归位;review → 并入 design;hotfix → 并入 app
```

- 问题 1 ⇒ 规则 1(每仓一条,链条主体收进单 lane;跨仓只剩「收 pin」一跳,有明确协议)。
- 问题 2 ⇒ 规则 4 前半(接缝表)。⚠️ 接缝计数要**分生产 / 非生产**:非生产引用(mock / 测试)
  与生产点并列计数,会抬高 breaking change 的预告等级 —— 实测一条缝因此被高估了整整一档。
- 问题 3/4 ⇒ 规则 3 + 裁撤职能 lane 时问「它的存在前提还在吗」,别问「它最近忙不忙」。
- 问题 5 ⇒ 规则 2(实现集中一条 ⇒ 同仓并发写从常态变例外;写冲突纪律仍要,但从「每天的事」
  降为「边缘情况」)。
- 问题 6 ⇒ 规则 4 后半(事件触发表)。

**裁决权与文件所有权可以分离**(值得单说):领域中性这类跨仓 invariant,门(测试)住被守的仓、
**判官(词表 / 豁免的裁决权)住仓外的裁决 lane** —— 被审对象自己改判据的通道从结构上关闭。

## 重划本身怎么做(执行经验,跑过一遍)

1. **先裁时序**:业务收尾和拓扑重切谁先?本次用户裁「先切」,风险补偿 = 接缝表 + 事件触发 +
   协调 lane 盯跨界刀。**把否掉的选项连同理由留档**(否则轮换后它会被重提)。
2. **多源 handoff**:每条旧 lane 只写自己域的交接节,新 lane 读齐**全部**来源后做 smoke
   (回显读过的清单 / cwd / 自己理解的边界),裁决 lane 逐条收 smoke 后才宣告迁移完成。
3. **换角色 ≠ 退役**:原地重 attach 带新 role(对话与历史保留)。退役是**终态**(对话回不来),
   只给「这条 lane 不再需要了」用。⚠️ 归档后的地址能否复用是**平台语义且随版本变**
   (本次一周内三封更正互相推翻)—— 写进项目文档时带日期与出处,别当永恒事实。
4. **新 lane 的 cwd 显式指定并让它自证**(`git worktree list` 看 cwd 在不在清单里)——
   实测有 lane 长期跑在已拆 worktree 的残留目录里,git 命令不报错但读数全错。
5. **role 换版时留一致性锚**:同一事实(如测试口径)只写一处,其余 lane 的 role 给指针。

## Anti-Patterns

| 反 pattern | 为什么错 | 修法 |
|---|---|---|
| 按技术子域切 lane(渲染一条 / UI 一条) | 代码会搬家,域跟仓渐行渐远,每刀跨界 | 按仓切;技术专长做「顾问」职能写进 role,不做边界 |
| 用「最近不忙」裁撤 / 保留一条 lane | 流量是结构性下界,忙闲读不出存在前提 | 问「它的存在前提(隔离树 / 独立判官 / 专属域)还在吗」 |
| role 里写测试条数 / 分支名 / 文件数 | role 不会变红,数字必过期且读起来永远像真的 | 只写归属边界,读数走 durable 指针 |
| 缝上的活「谁碰到谁处理」 | 互抓错全在缝上;两边都以为对方管 | 接缝表点名 owner + 两端同改时谁主导谁复核 |
| 复核依赖「记得在 pin 前进后查一下」 | 会漏,且漏的读数是绿的 | 事件触发表:挂 git 可观察事件,协调 lane 执行 |
| 为一次大审计加一条常驻 lane | 常驻成本换空转;且多一个吃 token 的会话 | campaign 制:临时开、审完归档 |
| 重划时顺手扩权(新 lane 比旧边界宽) | 拓扑变更夹带范围蠕变,没人审 | 每条新 role 过一遍「不做」清单,由裁决 lane 收 smoke |
