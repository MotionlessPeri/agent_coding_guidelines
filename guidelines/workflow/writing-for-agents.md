# 给 agent 写文档：指针、层级、完成判据与剪枝

写任何给 agent 读的东西都用这一页：skill、`AGENTS.md` / `CLAUDE.md`、被指针引到的说明页。包装不同，写法相同；目标是让 agent 每次走**同一个过程**，而不是产出同一份结果。本页是有来源的参考综合（见文末），不是硬规范；判据有争议时，用目标模型跑一遍文档来定，不靠辩论。

## context pointer：措辞决定能不能被够到

**context pointer** 是常驻在上下文里、指向上下文外材料的那一行：skill 的 `description`、根入口里的一条链接、索引表的一格都是。决定 agent 什么时候去读那份材料的，是这一行的**措辞**，不是材料本身。必须读的材料挂在一句含糊的指针后面，就是方差来源：先把措辞磨尖，磨不尖再考虑把材料内联。

一条指针做两件事：说清材料是什么；列出该去读它的**分支**（文档要处理的不同情形）。常驻的每个字每轮都要付费，所以指针要比正文剪得更狠：

- 触发词放在最前面，它是这一行真正干活的部分。
- 一个分支一个触发词；同一分支的几个同义词合成一个。
- 正文已经交代的身份介绍，不在指针里重复。

## 两种负载

- **context load**：常驻材料占的窗口与注意力，不管用不用得上，每轮都在付。
- **cognitive load**：人要记住有哪些文档、什么时候找哪份。人是索引；这是人保留控制权的代价，花在需要人判断的地方，其余地方去掉。

藏在指针后面的材料只付那一行指针的常驻成本；连指针都没有的材料，全靠人记得。

## 信息层级

文档由两种内容组成：**步骤**（agent 按顺序做的事）和**参考**（按需查的定义、规则、事实）。每块内容放在层级的哪一档，按 agent 多急着要它来定：

1. 文件内步骤：主档。
2. 文件内参考：按需查。一组平级规则排成一排是正常形态，不是缺陷。
3. 外置参考：拆到别的文件，只有指针触发时才读；可以是同目录附件，也可以是任何文档都能指向的外部资料。

压得太少，顶层臃肿；压得太多，agent 需要的东西被藏起来。**progressive disclosure** 的判据是分支：每个分支都要的就内联，只有部分分支走得到的就放到指针后面。有步骤的文档里堆着本该外置的参考，会把步骤埋掉，agent 注意不注意到它们就成了随机事件。

**co-location**：一个概念的定义、规则、例外放在同一标题下，读到一处就带出邻居。它跟重复不同：重复是同一个意思写两遍，散落是一个意思拆碎在多处。

**sprawl**：文档就是太长，哪怕每行都有用。修法还是层级：参考外置，按分支或按顺序拆开，让每条路径只带它需要的。按长度拆的经验阈值见 [`documentation.md`](documentation.md)，两者互补。

## 步骤的完成判据

每个步骤都以一个**完成判据**结束，告诉 agent 这一步做完了没有。它有两个性质：

- **清晰度**：agent 能不能分出做完和没做完。含糊的判据（「理解到位」）会诱发提前收工：后面还看得见的步骤是拉力，判据的清晰度是阻力。先磨判据；判据本质上就模糊、而且确实观察到在赶，才把后面的步骤藏起来。藏只在跨过真实上下文边界时才有效，比如交接或派子代理；同一上下文里内联调用不清掉任何东西。
- **要求度**：判据要求多少。「每个改过的模型都有交代」逼出彻底的工作，「列出改动」逼不出。要求度决定 agent 会不会主动多挖一层，而且它不只约束步骤：「每条规则都应用过」对一组平级参考同样有约束力。

最好的判据既能核对，又要求穷尽。

## leading word

**leading word** 是模型预训练里已经有的一个紧凑概念，agent 一边执行一边拿它思考：_lesson_、_tracer bullets_、_red_。把它当词重复使用，不展开成句子，它会累积出一个分散的定义，用最少的字锚住一整片行为。自造词也行，但它不带任何先验，定义要自己付字数；先找现成的词。

它锚两次：在正文里锚执行，agent 每次看到都做同一类事；在指针里锚触发，同一个词出现在你的提示、文档和代码里时，agent 更可靠地把它们连起来。三处各写一遍的同一组形容词、指针里用一整句比划一个概念，都是可以收成一个词的地方。

**否定会失效**：用禁止来引导，会把被禁的行为拽进上下文，让它更容易出现。写正向的目标行为，让被禁的那个根本不被提起。禁令只在写不成正向的硬护栏上保留，而且要配上正向目标。审查侧的同一现象见 [`adversarial-verification.md`](../../techniques/adversarial-verification.md) 的「否定式约束」一节。

## 剪枝

- **单一事实源**：一个意思只住一处，改行为只改一处。重复不只是维护成本，还会把这个意思在层级上的地位抬得比它实际高。
- **环境也是事实源**：`package.json` 脚本、配置文件、目录结构、`--help` 输出。文档重述它们就是缓存，只有查起来很贵时才值得。该写进文档的是查不到的东西：没写下来的约定、选择背后的理由、配置不会告诉你的坑。
- **相关性**：逐行问它还跟文档要做的事有关吗。不剪的默认结局是沉积：加东西感觉安全、删东西感觉有风险，过期的层一层层压下来，最后得往下挖才找得到还活着的部分。
- **no-op 逐句测试**：模型默认就会做的事，写出来是白付成本。判据是「这句改变了默认行为吗」，它是相对模型的，不是相对读者的：两个人对一句话是不是 no-op 有分歧，分歧在于默认行为是什么，用目标模型跑一遍来定。不过关的句子整句删，不在里面抠字。弱到压不过默认值的 leading word 也是 no-op，修法是换更强的词，不是换手法。本仓经验页的「复测」就是这个测试的批量版，见 [`instruction-content.md`](instruction-content.md) 的「经验随模型过期」。

## skill 的调用方式

由模型自动调用的 skill 要常驻一条 `description`，换来 agent 和别的 skill 能自己够到它；只由人调用的 skill 不占常驻成本，但要人记得它存在。本仓的共享 skill 只用可移植的 `name` / `description` 两个字段，所以都是模型可调用的；`description` 就是它的 context pointer，按上面的指针写法写。
