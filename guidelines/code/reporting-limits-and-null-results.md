# 报结论的三种静默错法:限制归错层、零结果读错量、"没有"读成事实

## 核心规则

有一类错误**不在工作里,在结论里**:代码写对了、测量跑对了,但**报出去的那句话**错了。危害比普通 bug 大——下游拿着错结论行动,而错的那句话读起来完全合理,没人会去质疑。

四条规则,各对应一种错法:

1. **报"做不到"时必须说清是哪一层做不到、以及是对哪个解法做不到。** 把**自己这层的收窄**说成**下层 / 框架 / 对方的能力边界**,会让人以为不可行,从而放弃本来能做的事。反方向同样错:把**自己这层的扩展**说成下层的能力,会让人按一个不存在的能力去设计。
2. **"改了参数结果没变"这个信号只能在原始输出上读,不能在聚合统计量上读。** p95 / 最大 / 均值天生只反映分布的一头,那一头恰好对某参数不敏感时,就会给出"参数没接上"的假信号。
3. **报"没有 / 找不到 / 没发生"之前,先问一句:我能到达的范围,是不是就是全部范围?** "真的没有"和"我看不到"**在观测上长得一模一样**,而人默认取第一种解释。
4. **一个数字要跟着它的机制一起走。** 机制没查 ⇒ 不能把这个数写成某个东西的**性质**;机制不适用 ⇒ 不能把这个数**搬**到别处。**而数字本身在两种情形下都长得一样可信。**

四条是同一个形状的四个面:**都是把一个局部结论说成了全局结论,而局部的边界没写出来。** 规则 1 漏的是**层**的边界,规则 3 漏的是**范围**的边界,规则 2 漏的是**量**的边界(你比的是哪个统计量),规则 4 漏的是**机制**的边界(这个数在什么条件下才代表你说的那件事)。

跟 [`diagnose-before-fixing.md`](diagnose-before-fixing.md)(动手修之前先取证)和 [`validation.md`](validation.md)(改完怎么验证)正交:那两条管**做**得对不对,本条管**说**得对不对。

## 规则 1:限制必须标明归属层

### 判据
写下任何"做不到 / 不支持 / 是它的设计约束"之前,问一句:**这个限制是我这一层造成的,还是我下面那一层真的没有?** 答不出来就先去核,别写。

尤其当你自己就是那层的作者时——**人对自己写的收窄有盲区**:它在你脑子里是"现状",出口就成了"约束"。

### 第二问:这个"做不到"是对**某个解法**证明的,还是对整个**层**证明的?

写下不可能性断言时,作者脑子里往往有一个具体解法,而那个解法确实不通。可是句子丢掉了"对哪个解法"这个量词,就变成了对整个层的能力断言——而读者(尤其照着规格干活的 agent)没有理由质疑它,于是照做,一条真正可行的路被封掉。

⇒ **把解法写进句子里**:"沿『先剥掉 X 再重算』这条路在接收端做不到"可以;"接收端解不开"不行。前者留着别的解法的门,后者把门关死。

**这条规则同样适用于你继承来的权威文档。** 照规格执行时,它的禁止条款不是物理定律——它也是某人写的一句话,也可能漏了量词。收到"你那边做不到"时追两句:**哪一层做不到、对哪个解法做不到**。

### 反方向:把自己这层的**扩展**说成下层的能力

规则 1 的镜像面,而且更隐蔽:**在当前环境里它真的能跑,你手上有活生生的正面证据**。典型形态是环境里有个被内部改过、而你以为是原版的组件——你把它的能力当成框架的能力报出去,下游按一个不存在的能力去设计。

配套的处置纪律:**一旦确认某做法在原版下不成立,就不要留 deferred 项、也不要留 stub 接口。** deferred 和 stub 都编码了"这条路通、只是还没接"这个判断;当这条路是被**否证**而不是被推迟时,留下的接口是假路标,下一个人会朝它建设。删干净,并把"以后若真有此需求,那是在新约束下重新设计的新问题"写进结论。

### 受害对象里最贵的一类:用户的数据 / 产物

现有各例被归错的对象都是框架 / 库 / API / 搜索范围。还有一类要单列,因为**它的归错代价不对称地高**:把自己这层刚引入的 bug 说成"用户交来的那份文件可能坏了"。

差别在**下一步动作**:对框架能力的误判通常只是让人放弃一条路(可逆);而"用户的产物坏了"的自然下一步是**丢弃或重做那份产物**,而且丢掉不会有任何报错。

⇒ 可执行触发器:**写下"用户的数据 / 产物可能坏了"之前,先自查一次"我这层最近改过什么"。** 尤其当你的代码就跑在读取那份产物的路径里时——插件跑在宿主的加载器里、你的 hook 挂在对方的流程上——**你是嫌疑人,不是旁观者**。

### 分层的样子(域相关,重点是每行"在"上一行下面)

| 层 | 这层的收窄举例 |
|---|---|
| 我的接口 / 契约 / 包装 | 字段声明成 `Optional[dict]`(其实底层收 list)、参数没暴露、便利层的白名单漏了某项 |
| 我的移植 / 实现 | 只搬了原实现的一半、某分支没写 |
| 我依赖的库 / 框架 | 真的没这个 API、真的是 stub |
| 底层原理 / 数学 | 几何上无解、信息量不足 |

**越往上越容易被误报成越往下的。** 报限制时把层写出来,读者才知道"能不能通过改我这层来解决"。

### "对的症状挂在错的对象上"比整句错更难被发现

规则 1 的一个高危形态:断言"不实现 X ⇒ 会出现症状 Y",其中 **Y 真实存在、X 归错了对象**。读者能自己复现 Y(可验),却验不了"Y 是不是 X 造成的"(要读他拿不到的源码)——**可验的那半替错的那半背了书**:他验到"果然有 Y",连带确认了错的 X;照做后 Y 仍在,此时他更可能怀疑自己实现错了,而不是怀疑那句断言。实测:一份接入文档写"视口不实现某方法 ⇒ 拖拽后没有撤销",症状为真,而成因实际在读者自己那层(没人替他 push 撤销记录)——照做的读者会白实现一个方法,然后回到同一个症状。

⇒ 写法纪律:**症状一句、成因一句,拆开写**;别用"不实现 X ⇒ 会 Y"把可验与不可验焊在一起。(单项目一击,机制清楚;是规则 1"归错层"在文档写作面的形态。)

### 证据(跨 2 项目,6 次独立复现,归错的层 / 方向 / 受害对象各不相同)

| 报出去的话 | 真实归属 | 代价 |
|---|---|---|
| "这个算子从不解决 A-vs-B 那类穿插,这是它的能力边界" | **移植只搬了原算子 930 行里的 125 行**,少的那半正是解 A-vs-B 的(且在原框架里**默认开**) | 一个可用能力被判为不可用;协调者(我)还把这句原样转给了第三方 lane,污染面扩大一圈 |
| "契约表达不了挂两份算子,已请上游裁" | **自己写的 `Optional[dict]`** 造成的;底层 vector + binding 一直支持挂多份 | 一次无谓的上游请求 + 被迫取折中配置(某部位的功能整个做不了) |
| "依赖离线人工标注 → 不适用" | 烘的是**可自算的几何**、且运行时**不需要**那份输入 | **整个能力被 park 掉**,几周后才被翻回来 |
| 交接规格写"这个镜像藏在四元数里、**接收端解不开**",并明确指示"别在接收端事后转一下" | **对某个解法证明的**:"先剥掉运行时算的那个变换、再用新的重共轭"这条路确实不通(协议里没有那个字段)。而同一份规格自己的数学在接收端有等价实施(对静止几何与流数据施加同一个反射),前提是骨架左右对称 | 该断言被 agent 忠实继承、又转发一圈(**污染面按转发次数放大**)。若一直信它,那次交付**直接做不成**——后来实测发现镜像不止影响观感,它让重定向的方向**反转**(源抬左手 40cm、目标降左手 36cm),连"先接受镜像"这个退路也不成立 |
| "这份 fbx 打不开,可能是它坏了"(用户交来的场景文件) | **自己这层刚引入的 bug**:插件把启用状态序列化进了场景文件,宿主重开时恢复它,于是插件的启动逻辑(阻塞握手 + 建对象 + 起线程)在**加载中途**跑起来 —— 症状是"文件打不开"。修法是加载期守卫 | 差一步把一份内含生产同事手调的 17 项参数的交付文件判为损坏。**丢弃或重做那份产物是这个判断的自然下一步,而且丢掉不会有任何报错**;后来那次绕开宿主、用格式 SDK 直读的抢救(17/17 命中)正是这次误判的代价下界——它本来根本不必发生 |
| "旧插件用自定义属性把时码流到下游,这个做法可用,记为 deferred 以后接" | **反方向**:靠的是环境里那份**被内部改过的**桥接插件,原版流不了自定义属性,而新管线用原版。⇒ 把自己这层(fork)的**扩展**说成了下层框架的能力 | 一次 correction 往返 + 差点留下一个 deferred 项和 stub 接口("这条路通、只是还没接"),而实际上它是被否证的 |

前三次都由**外部追问**打破(两次是用户直接质疑"这不对吧",一次是别人复核源码),**没有一次是自查发现的**;后三次同样如此(一次被实现实验打破、一次被用户点出、一次由第三方复核)—— 这正是为什么它需要成为一条明写的规矩,而不是靠自觉。

后三例出自**同一天的三条互不通气的 lane**,归错的维度各不相同(解法→层的外推 / 受害对象是用户的产物 / 方向反过来),而其中一次是"**照规格执行**"造成的——即这条规则必须覆盖**继承来的权威文档**,不只覆盖自己的回报。

### 相关但不同
[`../../techniques/adversarial-verification.md`](../../techniques/adversarial-verification.md) 的"量具先自证"讲**自己两份数据打架时先认自己不确定、不要判对方**。本规则是它的推广:**不只是"别判对方错",还包括"别把自己的没做说成对方的没有"**。

## 规则 2:零结果信号的有效范围

### 判据
"我把参数从 X 扫到 Y,输出没变 → 所以这个参数没接上 / 不起作用"——这是个**好用但容易失效**的信号(它是"可证伪"的一种廉价实现)。它只在**逐位比较整段原始输出**时成立。

一旦你比的是**聚合统计量**(p95 / 最大 / 均值 / 某个评分),"没变"就可能只是说明:**那个统计量看的那部分数据,恰好对这个参数不敏感**。

### 机制(实测)
一个按速度阈值决定是否"锁住"的算子:阈值扫 60 倍,**p95 与最大值三档完全不动** → 初判"参数没接上 / 主导因素不是阈值"。

逐位复验后真相是:**阈值确实接上了**(相邻阈值两两比,最大差 4.27 cm、8338/8417 帧有差别),中位偏差随阈值**单调下降** 2.71 → 0.21 cm。不动的是**大偏差那一头** —— 因为高速帧(占 26.4%)在**每一档下都判"没锁住"**,行为一致,而大偏差全出在这些帧上。

→ **p95 / 最大对该参数天生不敏感,中位才是它改变的那部分。**

### 正确做法
- 判"接线通不通"只用一个方法:**比整段原始输出是否逐位相同**。一行的事,别用统计量代劳。
- 报"某参数不起作用"时,**说清你比的是什么量**;若比的是聚合量,只能说"该量对它不敏感",不能说"它不起作用"。
- 这跟 [`../../techniques/adversarial-verification.md`](../../techniques/adversarial-verification.md) 的"metric 选错,缺陷会看小一个量级"是**同一枚硬币的两面**:那条说"聚合量会把缺陷看小",本条说"聚合量也会把参数的作用看没"。

### 另一个面:**事件**聚合会把频次看没(不只**数值**聚合)

上面讲的是 p95 / 均值这类数值聚合。同一个机制还有一个更常撞的形态:**日志行是"事件的聚合后表示",不是事件本身**——所以"日志里只有一行"不等于"只发生了一次"。

⇒ **拿日志判"某错误发生了几次"之前,先确认这条消息走的是普通日志还是去重通道。** 走去重通道时:

- 重复命中默认**不再输出**(第二次起就没有新行了);
- 行内那个计数**可能是永不更新的快照**——它在写日志那一刻求值一次,面板重绘时才重新求值,所以**日志文件里那行会永久停在"01"**,哪怕实际发生了 900 次;
- 面板给的计数也可能只是"自上次清理以来"(界面刷新会把计数归零重数),不是绝对总数。

实测形态:30fps 的流送里每帧失败持续一整分钟 = **1800 次事件 = 日志 1 行、且显示 01**。差一步就把它报成"只发生一次、偶发抖动、忽略即可",而角色其实一直冻着。

⇒ 现场判"还在不在发生"用**直观信号**(对象是否还冻着 / 状态灯颜色),别试图从日志推次数。要绝对次数就去查那个日志系统自己的计数查询接口——但先问一句现场有没有人会去调它。

其他日志系统有同类去重(`message repeated N times` 之类)是**合理推断,未实测** —— 所以这条写成"**先确认有没有去重**"的问法,不是"日志系统都会去重"的断言。

## 规则 3:"缺席"有两种成因,它们产生同一个观测

### 判据

写下任何"没有 / 找不到 / 不存在 / 没发生 / 零命中"之前,问一句:**我能到达的范围,是不是就是全部范围?**

因为**缺席有两种成因**——

| 成因 | 观测 |
|---|---|
| **真的没有** | 找不到 |
| **我看不到**(在我可达范围之外 / 我的探测器对它盲) | 找不到 |

**两者长得一模一样,而人默认取第一种。** 这条规则的全部内容就是把这个默认打断一次。

它是**读者侧**的规矩,不依赖写的人做对事 —— 这是它比"写清楚证据在哪"更可靠的原因(见下"配套的写者侧做法")。

### 实例(同一天,七次,六个不同技术域)

| 形态 | "找不到"实际是 |
|---|---|
| 一个只在数值**变化**时报警的 gate | 对"这个量**从来就没有过**"是盲的 —— 它只会报"变了",不会报"一直没有" |
| 对照组与实验组给出**同一结果** | 可能是"没有差异",也可能是**对照组根本没跑**(见 [`../../techniques/adversarial-verification.md`](../../techniques/adversarial-verification.md) "对照组自己也需要被验") |
| 审计一份文档,判某条断言"**无刻画记录 / 无依据**" | 证据存在,但住在一个**从这份文档无法到达的仓**(被 gitignore 的独立仓)⇒ 任何对该仓的审计都会得出同一个错结论 |
| 消费方查"库里有没有 X",grep 零命中 | 查的是 `external/<lib>/` —— **消费方能到达的全部,但不是库的全部** |
| 扫遍某工具集找不到程序化入口,报"**这个框架不支持程序化配置**" | 只扫了**那个工具集**;框架自己的脚本 API 里是完整的两个控制器(共 157 个成员) |
| 按 `*rig*` / `*ik_*` 文件名模式扫一个目录,报"**这个资产没有配套的 X**" | 它叫 `PA_<名>` 且住在**另一个目录** —— 文件名模式和目录范围**两条都躲开了**。差一步就建出重复资产 |
| 探测一个类名 → 返回 `ABSENT`,差一步报"**框架没有这个工厂**" | 探的是**自己猜的名字**:真名少一个 `-er`(`UIKRetargetFactory` 而非 `UIKRetargeterFactory`) |
| 报"日志里零命中 ⇒ 修复后没有复发" | 观测窗口被"**哪个日志文件**"隐式界定,而文件边界跟"修复之后"这个窗口边界不一致 —— 可能更宽(跨了修复点,历史污染),也可能更窄(日志因重启翻篇,运气好)。⇒ **窗口要用时间戳显式界定,不能用文件容器代替** |

第四例的报告者事后自评:"**我当时没说这句边界,是运气好结论没错**"——这正是这条的价值:**它这次没咬你,不代表下次不咬。**

后三例出自**同一条 lane 的同一天**,三次的可达范围边界各不相同(工具集 / 文件名模式+目录 / 猜的名字),而**第三次是它自己在写回执的过程中抓住的** —— 因为规则 3 那一问当时已经带在手上。

### 子判据:`ABSENT` 最危险的一种,是你探错了名字

上表最后一例值得单列,因为它给出了一个**比"声明可达范围"更锋利、可当场执行**的问法:

> **凡是"探测返回不存在",先问:我探的这个名字 / 路径 / 接口,是我 _查到_ 的,还是我 _猜_ 的?**

猜的就去权威处(框架源码 / 资产自己的属性 / 官方索引)**对一次名字**,再下结论。

**为什么它比别的形态更危险**:`ABSENT` / `None` / `零命中` 读起来跟"不存在"**一模一样,且不带任何征兆**。少一个字母、大小写不同、命名空间不同、单复数不同 —— 探测器全都老实返回"没有",而**它返回的是关于你那个字符串的真相,不是关于世界的真相**。

⇒ 一般化:**任何"按名字/模式查"的否定结果,其有效性上限是"这个名字/模式是对的"**。名字没核过,否定结果就什么都没证明。

### 镜像形态:**在场**也会被误读成完整

上面全部是"缺席被误读成事实"。反过来同样成立,而且同样系统性:**"容器存在"不等于"内容存在"。**

实测形态:检查三个第三方依赖在不在,`ls -d <三个目录>` **全部存在** → 极易据此报"依赖齐全,问题在别处"。真相是发行版裁剪掉了源码,只留下**目录骨架和许可证文件**(许可要求文件必须留着,所以骨架一定在)。⇒ 在这个场景里,"目录在"是**系统性的假阳性**,不是偶然。

⇒ 判据同规则 3 的那一问,只是换个方向:**我看到的这个"在",是我要的那个东西在,还是只有装它的壳在?** 凡是"存在性检查"落在容器(目录 / 表 / 配置节 / 包)上,就再往里查一层具体的物。

### 配套的写者侧做法:记"证据在哪",不只记"结论是什么"

读者侧那一问是兜底;写者侧能把这个坑填掉大半 —— **durable 文档里的断言要带证据指针**。但指针够不够,**取决于目标可不可达**:

| 情形 | 指针够不够 |
|---|---|
| 目标在**同仓**、或读者手上一定有 | **指针就够** —— 跟着走能看到全部细节;摘录反而制造两份会漂移的副本 |
| 目标在**另一个仓 / 另一个系统**,而它可能根本不在读者手上 | **指针不够,必须连关键证据一起摘** —— 否则读者只是从"没有证据"变成"有个我打不开的链接",**结论一样下不了** |

摘的标准是:**读者不打开目标也能判断该不该信**(实例:属性名与默认值 / 单变量隔离表 / 拆混淆变量的方法 / 已知未钉死的部分 / 复现脚本路径),不是把全文搬过来。

### 跟规则 1 的关系

规则 1 说"报**做不到**要说清哪一层",规则 3 说"报**没有**要说清哪个范围"。**同一个病**:局部结论说成全局,而局部的边界没写出来。区别在于规则 1 的边界是**层**(垂直),规则 3 的是**范围**(水平)。

## 规则 4:一个数字要跟着它的机制一起走

### 判据

写下任何"**X 的性质是 N**"或者把一个数**搬到另一个场景**之前,问一句:**这个数的机制,能预测我正在说的这件事吗?**

答不出机制 ⇒ 这个数只是**一次观察**,不是那个东西的性质。

### 为什么它比前三条难自查:**数字比文字更像证据**

前三条的错法起点通常是**文字**(一个参数名 / 一句注释 / 别人的措辞),而这一条的起点是**一个真实测出来的数**。
⇒ 于是"我该去查机制吗"这一问**不会被触发** —— 你手上有数,而数看起来就是证据。

### 两种形态(实测,跨 2 项目)

| 形态 | 实例 |
|---|---|
| **数字有了、机制没查** | 一个参数 `alpha=0` 时"行为在两种坐标约定下相反"被写成该参数的性质。真相:那个参数是**对整个向量做一次 `Lerp`**、三分量一视同仁 ⇒ **结构上不可能按轴表现相反**;那两个数里有一个是在坏构型下测的,它反映的是"整条管线喂了错数据",不是参数的性质。**一行 `Lerp` 对一下就知道。** |
| **机制都对、但搬到了机制不成立的地方** | "源侧推法的不确定度 = 被消费量的 28–67%"有完整机制支撑(两种推法 ⇒ 接触点不同),却被外推到另一个消费方的对照上——**而那边走真实网格顶点,"靠推"这个误差源根本不存在。** |

### 派生的两条(同一个骨架:只取证据链上一个点,然后把结论外推到整条链)

- **按名字查的零命中,只证明"这个名字没有",不证明"这件事没做"。** 功能可以用**另一个名字、在另一层**实现。
  实测:某顺序约束的逐对声明接口在三个算子里 grep 零命中 ⇒ 被报成"框架不拦顺序";而约束是用**另一个机制、在另一个文件**(处理器级遍历)表达的,且那处源码明写了为什么不用逐对声明。
  ⚠️ 这跟规则 3 那条子判据(**探测返回不存在时,先问那个名字是查到的还是猜的**)是**两件事**:那条是名字错了,这条是**名字对、而那件事换了机制**。
- **从一处消费点推"它在别处不被消费"同样错**,而且这两个错**外推方向相反**(一个从上游推下游,一个从一处推全体)⇒ 问题不是"某个方向容易错",是**"只取一个点"这个动作本身**。
  ⇒ 可执行:**读一个参数时,先 grep 它的名字拿到全部出现点,再决定读哪几处。**

### 诚实边界

跨 2 项目、双方各命中两种形态;"数字比文字更像证据"这个解释是双方共同定稿,但**未跨人 / 跨团队验证**。apply-and-refine。

## Anti-Patterns

| 反 pattern | 为什么错 | 修法 |
|---|---|---|
| "这是它的能力边界" / "框架不支持" —— 不说是哪一层 | 读者无法判断能不能靠改上层解决,可能放弃可行路 | 写明层;答不出来先核再写 |
| "搜了没有 / 零命中 / 不存在" —— 不说搜的范围 | "真的没有"与"我看不到"同一个观测,读者无从分辨 | 带上可达范围(搜了哪些仓 / 盘 / 目录 / 版本),或明说"在 X 范围内没有" |
| 拿"我记不清"直接推出"需要先做一件前置工作" | 那件前置工作可能根本不必要;答案常在自己的 durable 文档里 | 先查自己已有的记录,再判断要不要开新工作 |
| durable 文档只写结论、不写证据在哪 | 后来的审计(包括你自己)会判它"无依据" | 断言带证据指针;跨仓时连关键证据一起摘 |
| 自己是那层作者,却把自己的收窄当"现状"报出去 | 对自己写的约束有盲区 | 报限制前专门查一遍"这是我写的吗" |
| 拿 p95 / 最大 / 均值 判"参数没接上" | 那个量可能对该参数天生不敏感 | 逐位比原始输出 |
| 主指标变好就采纳一个改动 | 主指标看不见它破坏的别的维度(如姿势被拧坏) | 同时报会被它牺牲的量 |
| 上游收到"做不到"就直接转发下游 | 错结论的污染面按转发次数放大 | 转发前追一句"哪一层做不到、对哪个解法做不到" |
| 照规格执行时把它的禁止条款当物理定律 | 规格也是某人写的一句话,也可能漏了"对哪个解法"这个量词 | 审它的证明范围;规格说"你那边做不到"时同样追那两句 |
| 报某能力可用,却没查环境里那个组件是不是被改过的 | 反方向的归错:把自己这层(fork)的扩展说成下层框架的能力,下游按不存在的能力去设计 | 报能力前查一遍"这是原版吗";已否证的做法**不留 deferred、不留 stub 接口** |
| 写"用户的数据 / 产物可能坏了",没先自查自己这层 | 这个方向的误判会引出破坏性动作(丢弃 / 重做 / 覆盖),而且丢掉不报错 | 先问"我这层最近改过什么";你的代码跑在读取路径里时,你是嫌疑人 |
| 数日志行判某错误发生了几次 | 走去重通道的消息:重复不落行、行内计数是永不更新的快照 | 先确认有没有去重;现场判"还在不在发生"用直观信号 |
| 存在性检查落在容器上(目录 / 表 / 配置节)就下结论 | 发行版裁剪会保留骨架和许可文件,"目录在"是系统性假阳性 | 再往里查一层具体的物 |
| 把一次观察写成某个东西的**性质** | 数字比文字更像证据,所以"该查机制吗"这一问不会被触发 | 先问机制能不能预测这个观察 |
| 把一个有机制支撑的数**搬**到另一个场景 | 机制在那边可能不成立,而数字看起来一样可信 | 搬之前核那边的机制前提 |
| 按名字 grep 零命中就报"没做这件事" | 功能可以用另一个名字、在另一层实现 | 先问"这件事如果做了,可能长什么别的名字、住在哪一层" |

## 诚实边界

规则 1:**跨 2 项目、6 次独立复现**,归错的维度各不相同(层 / 解法→层的外推 / 方向反过来 / 受害对象是用户的产物)。后三次出自同一天三条互不通气的 lane,其中一次是"照规格执行"造成的。**已满足两击规则。**

规则 2:数值聚合那一面**单项目一次**(机制完全查清);事件聚合(日志去重)那一面**单项目一次**,目标系统源码级核实,"其他日志系统有同类去重"是推断未实测。

规则 3:**跨 2 项目、8 次同向命中 + 1 次镜像方向**,覆盖 7 个技术域(gate 覆盖 / 对照组 / 跨仓引用 / 消费方可达范围 / 工具集 vs 框架 API / 文件名模式+目录 / 猜的类名),分属**八条不同的 lane**;其中两次是当事人**自己没发现、被别人指出**的,**一次是当事人在写回执的过程中自己抓住的**(那时这条规则刚被交到它手上 —— 这是它当天就产生效用的直接证据)。各例的表层现象完全不同(告警盲区 / 两边一样 / 无刻画记录 / grep 零命中 / "框架不支持" / "资产没有配套项" / `ABSENT` / 日志文件当窗口 / 目录骨架还在),共同机制是同一个 —— 这种"表层各异、机制同一"比同一个坑踩九遍更有说服力。**已满足两击规则。**

⚠️ **仍未跨"人 / 团队"验证**:全部来自同一批协作对话,失败模式可能带有该环境的共性(高频跨边界转述、多方各持一部分可达范围)。在单人单仓的场景里它是否同样高发,未知。

整体 **apply-and-refine**。促升理由(为什么规则 2 不等第二个项目、以及为什么"差点发生"也算):它们不是"试了一次成功的做法",而是**有明确机制 + 可量化代价**的失败模式(一个能力被误 park 数周 / 一次误判接线 / 一份交付文件差一步被判损坏);且规则 1 的六次复现里,**没有一次是自查发现的**,靠外部追问才打破 —— 这类只能靠明写规矩兜的失败,越早写下越省。

### 一个反过来的观察:这条规则"生效"的次数天生数不准

规则生效(它当场拦住了一次误判)是这份语料库**唯一的投入产出证据**——命中只证明问题存在,生效才证明写下来的规矩真的拦住了问题。但这个数**结构性地只报下界,且偏差方向固定**:规矩内化得越好,错误状态越不成形,留下的痕迹越少。

判据是**那个错误状态有没有留下第三方能看见的痕迹**(一条真的写进候选清单的条目 / 一句真的准备发出的话)。只有自述"我本来会写 X、实际写了 Y"的,退回不可证伪一档。

一次实测的分布:同一天六条 lane 的收尾复盘里,按这个判据只有 **1 条**可出示的生效实例(某 lane 用本规则**否掉了自己一条候选**,那条候选连同理由完整写在它的回报里),另有 **4 条**是自述形态。⇒ 这个数只能作**存在性证明**用,**不能跟命中数并列读**,也不能因为它小就推断规矩没起作用——内化最好的那些恰好是隐形的那些。

**一条贯穿三条规则的观察**(来自规则 3 那轮的对话方,值得原样留着):

> 这类错**不发生在思考时,发生在表述时**。干活时你手上有证据,递结论时你手上只有印象,而印象需要一个凭据 —— 于是就近抓了一个。

⇒ 推论:**这三条规则的检查点不在"做完之后",在"往外说之前"**。同一天连撞三次同族错的那个人,三次全部发生在把结论递出去的那一刻,没有一次发生在干活的时候。
