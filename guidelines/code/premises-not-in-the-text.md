# 不在文字里的前提

凡正确性依赖一个不在它文字里的前提，它就会在别处静默失效，而它读起来永远是对的。可执行的一问：**这句话搬到另一台机器、另一个时刻、另一个人手上，还成立吗？** 本条补 [`reporting-limits-and-null-results.md`](reporting-limits-and-null-results.md) 四条边界之外的「前提」轴，并给两件工具：移动引用清单和作用域触发词。

## 前提住在哪些轴上

| 轴 | 它怎么骗人 |
|---|---|
| 时刻 | 配方里的 `HEAD`、分支名、「当前树」，目标一动就失效，文字一个字没变 |
| 机器 | 「本仓的 `core.autocrlf`」其实来自 system 层配置。「本仓实测」和「本机实测」是两个断言，「实测」这个标签也要写作用域 |
| 谁的树、谁的配置 | 共享工作区里别人的修复可能已进工作树；依赖 `core.*`、环境变量的判据换个人跑就换了含义 |
| 人员构成 | 「commit email 不是我们的域 ⇒ 外部改动」。变化最慢，所以最不像会过期，过期时没有近因提示回头看；还叠加「在哪个仓问」 |
| 作用域 | 「唯一 / 一律 / 全部」，发生在归纳那一刻，见下 |
| 相对时间量词 | 「最近三轮 / 至今 / 刚才那批」，含义随时间自变，且不长得像引用，扫词扫不到 |
| 改写、压缩、换受众 | 压缩最先丢的是限定词，它们看起来最像可省的修饰，而它们正是前提。这是动作型触发，任何一轴的前提都可能在这一步集体掉落；改写产物交付前对着原文逐条核限定词 |

## 移动引用换成不动引用

`HEAD`、分支名、「当前树」、「刚才那次」、文件里的行号、相对时间量词都是移动引用；`<sha>`、`<sha>^:<path>`、blob hash、冻结的清单、就地写下的名字是不动引用。行号可以在写下它的那次编辑里就失效，插入文本的动作自己把下方行号推走；修法是换掉指针（就地写名字），不是重算行号。收口、结项、复盘类判断给相对时间量词加不动的截止锚：「截至 `<sha>`」。

## 作用域缺失有触发词

把对某个子集证明的东西说成对整个类证明的，发生在归纳那一刻，归纳本身就是扩大作用域。触发词：**唯一、一律、都、必须、全部、从不、永久**。每写一个，回头指出它的反例应该长什么样；指不出来，说明作用域还没想清。

## 修法有优劣，次优解不是次品

最优是换一个没有那个前提的工具或不动引用，不要求任何人记得；次优是把前提写进文字，要求每个后来者都读到。但「换」常常不可得，实测四次命中里只有一次真换了实现。把本条读成「必须换掉那个东西」，会让人在换不掉时干脆不写，那是最坏的结果。本条的主要产出就是把前提写出来。

## 前提分两种，只有一种该被移除

可移除的前提换工具就没了，是缺陷；内在的前提是所问问题的定义的一部分（「两份文件是不是同一份」离开规范化约定没有意义），只能写出来并连取值一起记。测法两条合用：问「把这个前提移除，我还在回答同一个问题吗」；再去找零前提的版本。单用后一条会把可移除误判成内在，因为「找不到」有两种成因（问题的定义使它不可能，或当前条件使它不可得），而当前条件感觉起来是永久的。误判的代价在将来：标「内在」后没人回头捡；正确写法是「可移除，但当前不移除，理由是收益 / 成本」。把内在前提当缺陷去修，得到的工具更严格且答错问题，假红比假绿更能骗过想认真的人。

## 配方和读数的自证门槛不同

读数只需这次对；配方需要它依赖的前提全在它自己的文字里，照做的人不会知道那些前提。一条配方最可信的时刻，恰好是它刚碰巧对过一次之后。

## 反模式

| 反模式 | 修法 |
|---|---|
| 配方里写 `HEAD`、分支名、「当前树」 | 用 `<sha>` 类不动引用 |
| 用行号做跨文本引用 | 就地写名字或符号 |
| 收口、复盘判断用「最近 N 轮 / 至今」 | 加不动的截止锚 |
| 写「唯一 / 一律 / 全部 / 从不」不给反例形状 | 触发词自查：它的反例长什么样 |
| 把内在前提当缺陷去修 | 写出来，连取值一起记 |
| 「刚修好一个前提缺失」后放松 | 实测同一段对话连撞三次，每次都在「刚修好上一个」的状态下 |

## 证据

事故记录见本页 frontmatter 的 `incidents`，统计由 `kb.py index` 生成到 [`evidence/INDEX.md`](../../evidence/INDEX.md)。单日、单协作批次（四方并行对话）十余击，表层各异（git 配方、email 判据、行号、量词短语、压缩丢限定）而机制同一；未跨批次、跨团队验证。促升理由：这族失效全部静默，没有 gate 形态，只能靠明写的问题与触发词兜。
