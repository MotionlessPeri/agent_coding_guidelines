# 不在文字里的前提:判据、配方、结论的静默失效

## 核心规则

**凡正确性依赖一个「不在它文字里」的前提,它就会在别处静默失效——而它读起来永远是对的。**

可执行的一问:

> **这句话搬到另一台机器、另一个时刻、另一个人手上,还成立吗?**

这条跟 [`reporting-limits-and-null-results.md`](reporting-limits-and-null-results.md) 同族(局部结论说成全局,而局部的边界没写出来):那份管**层 / 范围 / 量 / 机制**四条边界,本条补**前提**这一轴,并给两件那份没有的工具:移动引用清单 + 作用域触发词。

## 前提住在哪些轴上(实测清单,非穷举)

| 轴 | 实例 | 它怎么骗人 |
|---|---|---|
| **时刻** | 配方写 `git show HEAD:<path>` 取「坏版本」 | fix 一提交,`HEAD` 就指向好版本,而配方文字一个字没变 |
| **机器** | 「本仓的 `core.autocrlf=true`」 | 实测它来自 system 层配置(不随仓库走)⇒ 换台机器,同一条命令不同口径。「实测」这个标签也要写作用域:「本仓实测」和「本机实测」是两个不同的断言 |
| **谁的树** | 「树现在是坏的」 | 共享工作区里,别人的修复可能已进工作树(未提交) |
| **谁的配置** | 依赖 `core.*` / 环境变量 / `PYTHONPATH` 的判据 | 换个人跑就换了含义 |
| **人员构成** | 「commit email ≠ 我们的域 ⇒ 是外部的改动」 | **变化最慢,所以最不像会过期的东西**——正因为慢,过期时没有任何近因提示你回头看。且实测它还叠加「在哪个仓问」:同一段代码在两个仓里 email 不同(跨仓搬运的 commit 顶替了原作者) |
| **作用域** | 「唯一 / 一律 / 全部」 | 见下节——它发生在归纳那一刻 |
| **相对时间量词** | 「最近三轮 / 至今 / 刚才那批」 | 见「移动引用」——它逃得过扫词 |

## 移动引用 vs 不动引用

| | 例子 | 什么时候失效 |
|---|---|---|
| **移动** | `HEAD` / 分支名 / 「当前树」 / 「刚才那次」 / **文件里的行号** / 「本仓的配置」 / **相对时间量词** | 目标一动就失效,而指针一个字没变 |
| **不动** | `<sha>` / `<sha>^:<path>` / blob hash / 冻结的清单 / **就地写下的名字** | 不失效 |

- **行号**:一个指针可以在**写下它的那一次编辑里**就失效——插入文本的动作自己把下方行号推走(实测:为消歧插入 14 行的一节,节内六个行号引用当场全错,其中一个最后指向它自己那一行)。修法是**换掉指针**(就地写名字 / 符号),不是**修指针**(重算行号——下次有人插入照样全错,且同样读起来完全正确)。
- **相对时间量词**:前几类移动引用是**可见的标识符**,对着清单扫词能扫到;这一类是**量词短语**,不长得像引用。对**收口 / 结项 / 复盘**类判断尤其危险——那些判断的内容恰恰是「最近没有新东西了」,而「最近」的含义随时间自己变。修法:加不动的截止锚(「**截至 `<sha>`**,最近三轮全是…」)。

## 作用域缺失有触发词,可机械查

把对某个**子集**证明的东西,说成对整个**类**证明的。机制:**它发生在归纳的那一刻**——归纳本身就是扩大作用域,所以那一刻天然缺一句「我这个证明覆盖到哪儿为止」。实测同日四方各犯一次(一个实例 → 整层禁令 / 修法层面的约束 → 「做不成」 / 手列的面 → 「仅此一处」 / 朝一个方向失效的那半 → 「唯一可用的形态」)。

✅ **触发词:「唯一 / 一律 / 都 / 必须 / 全部 / 从不 / 永久」**——每写一个,回头**指出它的反例应该长什么样**;指不出来,说明作用域还没想清。(跟 reporting-limits 规则 1 的「把解法写进句子里」同源;本条给的是检测手段。)

## 修法有优劣,而次优解不是次品

```
最优  换一个没有那个前提的工具 / 不动引用   ⇒ 不要求任何人记得
次优  把前提写进文字                       ⇒ 要求每个后来者都读到那句说明
```

⚠️ 但「换」常常不可得(实测四次命中里只有一次真换了实现——配方 `HEAD` → `<sha>^`;另三次能做的就是把前提写出来)。**把本条读成「必须换掉那个东西」,会让人在换不掉时以为自己失败了,于是干脆不写——那是最坏的结果。**本条的主要产出就是「把前提写出来」。

## 前提分两种,只有一种该被移除

| | 判据 | 处置 |
|---|---|---|
| **可移除** | 换工具 / 换不动引用就没了 | 是缺陷,该移 |
| **内在** | 它是**所问问题的定义**的一部分(例:「两份文件是不是同一份」离开规范化约定就没有意义 ⇒ filter 配置这个前提移不掉) | **写出来**,必要时连取值一起记 |

测法**两条合用**:

- **问法**:把那个前提移除,你还在回答同一个问题吗?是 ⇒ 可移除(只是贵);否 ⇒ 内在。
- **做法**:去找那个「零前提」的版本。找得到 ⇒ 可移除;找不到、且能说清为什么 ⇒ 内在。
- 🛑 **单用做法会把「可移除」误判成「内在」**——「找不到」有两种成因(问题的**定义**使它不可能 / **当前条件**使它不可得),而两种都说得出理由;当前条件感觉起来是永久的,这正是「变化最慢的东西最不像会过期」的同一个机制。
- 误判的代价在**将来**:标「内在」⇒ 后来者不再想它,条件变了也没人回头捡;标「可移除」⇒ 它留在待办的形状里,条件一变就有人捡起来。⇒ 正确写法是「**可移除,但当前不移除,理由是收益 / 成本**」,不是「内在,写出来就好」。
- 🛑 内在前提的另一面:把它当缺陷去「修」,得到的工具**更严格且答错问题**——**假红比假绿更能骗过想认真的人**。

## 配方和读数要有不同的自证门槛

```
读数  只需这次对
配方  需要「它依赖的前提全在它自己的文字里」——照做的人不会知道那些前提
```

实测:一条被标成「成本是一条命令」的验证配方,发出后数分钟内被另一方原样照抄——而它差两个不在命令里的前提;它当次给出的结论**碰巧**是对的。⇒ **一条配方最可信的时刻,恰好是它刚碰巧对过一次之后。**

## Anti-Patterns

| 反 pattern | 为什么错 | 修法 |
|---|---|---|
| 配方里写 `HEAD` / 分支名 / 「当前树」 | 把「什么时候跑」写进了正确性前提,而它不在文字里 | 用 `<sha>` 类不动引用 |
| 用行号做跨文本引用 | 插入动作自己推走目标,指针可在写下当刻就失效 | 就地写名字 / 符号 |
| 收口 / 复盘判断用「最近 N 轮 / 至今」 | 量词含义随时间自变,且扫词扫不到 | 加不动的截止锚 |
| 写「唯一 / 一律 / 全部 / 从不」不给反例形状 | 归纳时刻天然缺作用域声明 | 触发词自查:它的反例长什么样 |
| 把内在前提当缺陷去修 | 得到更严格且答错问题的工具(假红) | 写出来 + 连取值一起记 |
| 「我刚修好一个前提缺失」后放松 | 实测同一段对话连撞三次,每次都发生在「刚修好上一个」的状态下 | 修过 / 引用过 / 正在修同款,都不保护下一句 |

## 诚实边界

单日、单协作批次(四方并行对话)十余击:轴表各轴均有实测、作用域格四方各一次、行号与相对时间量词各一次。表层各异(git 配方 / email 判据 / 行号 / 量词短语)而机制同一。未跨批次 / 跨团队验证 ⇒ apply-and-refine。促升理由:这族失效全部静默(读起来永远对),没有 gate 形态,只能靠明写的问题与触发词兜。
