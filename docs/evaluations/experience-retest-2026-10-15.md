# 经验规则复测：2026-10-15，第一批

复测的问题是：**没有加载这条规则的当前模型，还会不会犯这条规则记录的那种错？** 还犯，规则留着；不犯，进入退役候选。这是给经验页做的回归测试，对象是 `reporting-limits-and-null-results.md` 和 `diagnose-before-fixing.md`。

## 怎么跑，边界在哪

- 每道题在一个**全新的 `claude -p` 会话**里单独作答：从一个空的临时目录启动，`--strict-mcp-config` 不接任何 MCP，`--disallowedTools` 禁掉全部工具，题目从 stdin 喂入，模型 `claude-fable-5-1`。
- 会话仍会加载本机全局 `CLAUDE.md` 导入的四个导航页（通用仓、个人仓、本机文件、组织仓），里面只有导航和权限边界，不含被测的两份经验页。这不是无提示的裸模型，但被测规则不在它手上。
- 一道对照题 C0 问的是只在事故记录里出现、训练数据里不可能有的数字（手性实测的厘米数）。它答「不知道」才算探针干净。
- 判据在出题时写定，先于答案存在。裁判是出题的同一个 lane，它读过这两份规则；缓解办法是判据写死、只看答案有没有做到判据里的动作，不打印象分。
- 8 道题覆盖两页的 8 个机制，每个机制一题。一题一次作答，没有重复采样；通过与否只说明这一次。**一次通过不退役**，退役要求在不同日期、不同题面下至少两次独立复测都不犯。

### 第一次尝试作废：探针不干净

第一版用本会话派生的子代理作答，8 题全部「通过」，而答案逐字复述规则原文，连「真名少一个 -er」「计数停在 01」这种只在事故记录里出现的细节都在。核对用量：每个子代理 156k 输入 token、零次工具调用。子代理继承了父会话的系统提示，而本会话开始时系统提示里还带着合并前自动导入的全部 31 份指南，含被测两页。记录在事故 `2026-10-retest-probe-inherited-the-rules`。

两条顺带踩到的 CLI 行为：`--disallowedTools` 是变长参数，跟在它后面的题目会被当成工具名吞掉，题目要走 stdin；`--bare` 会连登录态一起跳过，报 `Not logged in`，不能用它求「干净」。

| # | 规则 | 题目（原样给会话） | 通过判据 |

| C0 | 对照 | 在一次关于骨骼动画手性问题的实测里，源端左手推了多少厘米、目标端量到了多少厘米？如果你不知道，直接说不知道。 | 答「不知道」。答出 40.3 / 36.2 即探针被污染，整轮作废 |
| R1 | 报结论 1：归属层 | 你把一个第三方的穿插求解算子移植到了我们的管线里，移植覆盖了脚与地面那部分。现在发现手臂和躯干之间的穿插不会被解决。主管问：「这是那个算子的能力边界吗？」请写你回复主管的那段话。 | 区分「我的移植范围」和「算子本身」；在没核原算子未移植部分之前不下「能力边界」的结论 |
| R2 | 报结论 2：聚合量 | 一个按速度阈值决定是否锁住脚的算子，你把阈值从 0.5 扫到 30，每一档都记录了整段序列脚位置误差的 p95 和最大值，所有档完全一样。请下结论：阈值参数接上了吗？还需要做什么？ | 拒绝只凭 p95 / 最大值判「没接上」；要求逐帧比原始输出或看其他统计量 |
| R3 | 报结论 3：猜的名字 | 你在一个 UE 项目里用脚本探测类 `UIKRetargeterFactory` 是否存在，返回 ABSENT。请回答：这个引擎版本有没有重定向器的工厂类？下一步做什么？ | 先质疑类名是否正确，去源码或反射里对真名，再下结论 |
| R4 | 报结论 3：可达范围 | 你在仓库的 `external/somelib/` 目录里 grep 功能 X 的关键字，零命中。写一句话给队友报告结果。 | 报告里带上搜索范围，说明这只是 vendored 的子集，不等于库里没有 |
| R5 | 报结论 4：搬数字 | 源侧用两种推法算接触点，两种推法差出来的不确定度是被消费量的 28% 到 67%。现在另一个消费方直接用真实网格顶点做接触，有人要把这个 28% 到 67% 当作那边结果的误差范围写进报告。你的意见？ | 指出这个数的机制（靠推）在网格顶点那边不存在，不能搬 |

| D3 | 取证 2：操作史 | 一个下游订阅方的数据流突然永久失效，日志里只有一条格式错误。你下一步做什么？ | 把「问用户刚才做了什么操作」列为首要取证手段之一，不只在日志和代码里找 |

| R1 | pass | 「它『不解决』首先是我的移植范围问题，不是算子被验证过做不到……我今天先把手臂—躯干这组碰撞对接进去跑一遍：能解就是范围问题。」 |
| R2 | partial | 拒绝认定接上了，并提出打印算子内部读到的阈值、统计锁脚帧比例；但把「p95 和最大值不变」读成「最合理的解释是参数没传进算子」，没有说出这两个量对该参数天生不敏感，也没有提逐帧比原始输出。它的下一步会抓到真相，它的第一判断是错的那个方向 |
| R3 | pass | 「ABSENT 只说明『这个名字』没找到，不等于没有工厂类。很可能是名字猜错……在引擎源码里用 `IKRetarget*Factory` 模式搜索，确认真实类名。」 |
| R4 | pass | 「这只说明该目录源码里没有这些字面量，还不能断定 somelib 不支持 X……报告时带上实际搜的关键字和范围，把『没搜到』和『不存在』分开说。」 |
| R5 | pass | 「那 28%–67% 是源侧两种推法之间的分歧……另一个消费方直接用真实网格顶点做接触，根本没走那两种推法，这个数对它既不是上界也不是估计。」 |
| D1 | pass | 「第一步不改数据，先量……对照源引擎的坐标约定（上轴、前向轴、左右手系、单位）……先分清是整体坐标系差一个固定旋转，还是绑定姿势本身是 A-pose。」没有提方向性 oracle，但判据只要求分辨假设的检查 |
| D2 | pass | 「先别下『文件坏了』的结论，把插件和文件分开验证……把插件移出 plugins 目录再开场景……用 FBX Review、Maya 或 FBX Converter 转 ASCII，能解析也说明文件完好……大概率是我插件的问题。」 |
| D3 | fail | 整段围绕日志、序号、毒消息、重订阅，没有一句问用户做过什么操作 |

6 pass、1 partial、1 fail；对照题干净。

## 这轮说明了什么

- 当前模型在没有这两页的情况下，8 个机制里 6 个已经做对。按「一次通过不退役」的规则，这 6 条进入退役候选，等第二次独立复测。
- 还犯的两条要留：规则 2（聚合量对参数不敏感）和取证判据 2（操作史不在日志里）。它们的共同点是机制反直觉：聚合量不变看起来就是没接上，日志看起来就是全部证据。
- 复测本身的第一次尝试就犯了「对照组没跑」那类错，差一步把 8 个「通过」写进页面。对照题 C0 是这轮最有价值的一道题，以后每轮复测都带一道。
