# UE 渲染 LLM Wiki 小型试点

2026-10-13；本试点由用户同意后开展，采用模型维护 Markdown 综合页的方式。没有安装检索服务、增加全局技能或后台更新任务。

## 范围与实际产物

[试点入口](../../references/ue-rendering/wiki-pilot/README.md)包含两份互链综合页：自定义效果的扩展路径选择，以及版本与核验边界。五份原资料和读取范围见 [sources.json](../../references/ue-rendering/wiki-pilot/sources.json)。原资料继续保留；综合页不替代规范、不提高来源的证据等级。

来源基线是 `32ec133` 及清单注明的工作区导航增补。文件哈希按 UTF-8 去 BOM、CRLF 转 LF 后计算，章节定位说明实际使用了哪些内容。清单只帮助发现来源变化及定位依赖，不能判断结论是否正确。

## 三题探索性对照

一位 agent 从指定原资料按需阅读并回答；另一位先读 Wiki，再为核对摘要补读原章节。两者收到相同问题，没有读取对方答案。协调者按事先记录的内容判据复核；这是一组定向对照，不是盲测、随机实验或统计意义上的模型 A/B。

| 问题 | 原资料阅读 | Wiki 阅读与修订 |
|---|---|---|
| 全屏效果何时用材质、扩展点或改引擎；RDG 是否同层选项？ | 区分可用输入/阶段、现有接口限制和维护成本；说明 RDG 与接入边界的区别 | 初稿把修改既有 Pass 内部行为这个典型情况升为必要条件，已修正；另补充 RDG 层级解释，独立复核通过 |
| UE 5.8 与 5.5 有同名 CVar，能否保证参数和行为相同？ | 保留名称存在与行为证据的区别，要求对应目标版本及调用路径 | 同样保留限制；没有继承原表由部分名称缺失推断整个子系统不存在的扩大结论 |
| RDG 卡片核过 CVar，是否可直接使用其余全部 API 签名与样例？ | 否；保留 §8 CVar 与其他未逐条核验内容的区别 | 同样保留这个章节级边界，不把综合页写成代码已验证的保证 |

两个来源路径都能支持这些问题。Wiki 的初稿错误说明：综合会引入新的范围偏差，来源链接不能替代审查。这轮没有证明 Wiki 提高回答准确率。

## 读取成本的可知与不可知

Wiki 阅读组的初次阅读记录为：三份 Wiki 文本 14,502 字节，额外原章节 8,470 字节，共 22,972 个 UTF-8 内容字节。这个过程同时承担摘要忠实度审查，不能把额外阅读都当作普通问答的必要开销；数字对应初稿阅读，未把修订后的文件大小冒充当时读取量。

原资料组遇到输出截断和范围脚本多余输出，关键章节已补读，但未取得可靠的实际读入字节总量，因此不做两组读取量比较。上述数字也不含宿主指令、工具包装等，不是总上下文或 token。本轮不能报告 token、耗时或读取成本改善。

## 来源变化后的维护演练

在仓库外复制来源与 Wiki，保留 `before/`，仅在 `after/` 的扩展点卡片中合成撤回“签名、枚举、注册 API 已逐条核对”的声明，并明确标为 S1 演练。原候选路线与技术正文保持不变，正式来源不接受这项合成变化。

准备步骤只复制输入并检查差异：检测到一份来源变化、四份不变，两份依赖综合页仍是原文。另一位 agent 随后从差异实际阅读并维护私有 Wiki；判据是改写受影响的结论和答复，保留不受影响的概念，并在语义复查后更新依赖记录。仅修改哈希不算完成。

独立维护者实际改写了两页中的依据段、来源表、平台条件及答复示例，并补查入口 README。协调者读回来源差异与页面改写，确认旧核验声明没有继续作为有效依据；候选路线和 RDG 层级概念保留，撤回声明也没有被误写成接口已被证伪。维护前后两组各五份来源的哈希均与对应清单一致，合成来源仍与准备步骤记录的值一致。

演练还发现入口 README 自身也会缓存来源范围，不能只列两份综合页为依赖。正式清单已将入口加入依赖对象；这次发现说明依赖表需要随实际使用修正，不能把最初声明的列表当成完整影响范围。

本例完成了“发现一项来源变化→独立 LLM 重读并改写→另一位阅读者核对语义”的一次人工辅助维护。它没有证明无人值守更新、任意来源变动都能正确处理，或维护成本低于直接读原资料。

复现时可按上述步骤在独立目录构造同一撤回场景，使用入口中的只读哈希检查定位变化，再让维护者读取差异和依赖页。不要把合成输入或私有改写写回正式知识，也不要把一次人工辅助维护称为后台自动更新能力。

## 采用边界

保留这个单主题试点，用于需要跨文档解释的知识问题。更新依赖、证据边界与定向复核仍有维护成本；尚无依据将全库规范、全部领域资料都改成自动生成 Wiki。本轮没有运行 UE、重新核验引擎 API 或验证渲染效果。

交付时的结构检查覆盖六份改动 Markdown：70 个本地文件链接、19 个章节锚点均可定位；入口中的只读检查实际返回五份来源均未变化，15 个声明依赖目标均存在，`git diff --check` 通过。这些结果不代替上述语义复核，也不证明底层技术内容正确。
