# 报读数之前的四问:量具 / 样本 / 总体 / 判据

## 核心规则

一个读数可以在**四个不同的对象**上坏掉,而四种坏法的读数**看起来全都正常**——所以往外报任何测量结果(测试读数 / grep 命中数 / 扫描结论 / 对照实验)之前,要过的是**四个独立的问题**,不是一句「要小心」:

| # | 对象 | 问什么 | 便宜的自证动作 |
|---|---|---|---|
| ① | **量具** | 这个探针被**造过红**吗? | 喂一个**已知具有被测性质 P** 的样本,看它认不认得 |
| ② | **样本** | 喂了几个?正反两侧都有吗? | **A/B**:带 / 不带各跑一次,数数 |
| ③ | **总体** | 我在哪一批上量?它代表我要说的那批吗?**量具自己在不在里面?** | 三种失效三条动作,见下 |
| ④ | **判据** | 它答的是哪个问题?我要下的结论会通过它守的那道口吗? | 一句话,不用跑 |

实测背景:同一天、四条互相独立的并行协作对话把四个对象各踩了一遍(总体那格踩了三次),**七次实例的读数没有一次是可疑的**——「读数怪不怪」那套指纹在这四类失效上系统性哑火,所以只能事前问,不能事后看。

跟 [`adversarial-verification.md`](adversarial-verification.md) 的关系:①(量具)的细节——量具先自证 / 可疑读数指纹表 / **同型故障**(指纹表整族失效的那一类)——都在那份;本条给**组织形态**:四个对象各问一次,因为补好一格不覆盖其他格。

## ① 量具:造红,只是换了对象

「造红」不是新方法,是「注入一个已知的东西,看被测方认不认得」——人们对每一道**门**(产品侧的 gate)都造红,对**探针**(自己临时写的检查工具)几乎从不造,因为门是「产品」、探针是「工具」,而人不对工具做验收。探针坏法的实测形态:grep 模式写错(报 0 而内容在)/ 用行号定位内容(文件被追加过,行号早漂了)/ 求差指纹在混合改动下零信号 / 目测数清单数错。细节与「同型故障」见 adversarial-verification;这里只留动作:**喂已知答案**。

## ② 样本:判「起没起作用」跑 A/B,别用构造样本推

实测代价:一次「这条过滤子句是不是死代码」的判断,构造样本给出了**反向**结论(判「死代码」,真数据 A/B 显示它挡掉 4 条)。

- 判任何「这一步有没有起作用」都跑 **A/B**(带 / 不带各跑一次),不要推理。
- ⚠️ A/B 要求那一步**可关掉**;关不掉才退回构造样本,且标注写「**未验,且构造样本在此类问题上曾给出反向结论**」,不能只写「未验」。

## ③ 总体:三种失效,三条动作,互不覆盖

| 失效 | 实测形态 | 动作 |
|---|---|---|
| **A 这一批是少数派** | 拿 3 个「没碰过的」文件当对照组,而它们全落在全体 301 个里 25 个的少数派中 ⇒ 结论反了 | **报分母**(1 条命令的事,如 `git ls-files --eol \| awk … \| uniq -c`) |
| **B 量具自己在总体里** | 扫描器把自己的脚本算成「写过那个文件」 | **把量具自己喂给它**,它应当排除自己 |
| **C 总体随观测增长** | 那个数 4 → 5 → 6,涨的全是观测行为本身产生的 | **按「本次观测开始之前」截止** |

- 🛑 **报分母对 B / C 无效** ⇒ 补完一条要问「我刚补的这条,对同一格的**其他**失效有效吗」,不是问「这格补完了吗」——后者只看那格现在有没有内容。
- 📌 A 的关键区分:**判「代表不代表」贵,报「占多少」便宜**,而后者足以让「不代表」当场可见。一般化:「证明 X」和「让非 X 可见」是两件事,后者常便宜一个量级。
- ⚠️ 「报分母便宜」的前提是总体**有枚举器**(`git ls-files` / `ls` / `COUNT(*)`);「所有可能的用户操作」这类没有枚举器 ⇒ 退回点名样本 + 说明为什么拿不到分母。
- 🎯 ③ 有一条其余三格没有的性质:**它的错法随时间变化**(观测本身改变总体);其余三格量一次就定了。

## ④ 判据:「A 覆盖不了 X」有两种意思

```
A 有洞           ⇒ 该补 A
X 不属于 A 的问题 ⇒ 该另立判据
```

两者在句子里长得一样。判法:**问 X 会不会通过 A 所守的那道口**。实例:某类损坏在提交发生之前就已完成 ⇒ 它根本不经过「提交前读全 diff」那道口 ⇒ 那条纪律无需改动。说成「洞」的代价:有人会给一个已完整的判据**加一道无关的门**。

## 四问自己也会被同样的坑咬(真值有偏)

- 用有缺陷的真值评判别器,会得到**不存在的失败点**;下游据它建「不受该缺陷影响」的结论——而恰恰受影响。📌 **真值有偏时,受污染的不只是分数,还有「错在哪」**,而后者读起来像原始证据。
- 声明缺陷之后最危险的下一句是「**但有一部分不受影响**」——说这话的人通常只是**感觉**有一部分干净。✅ 判据:把那一部分**逐条列出,并对每条写出它的独立来源**。
- 「它没出错」≠「它是对的」:可能是**没被有效考过**(能考它的样本在这批数据里结构上不存在)。报「零错」时同时报**什么样的样本才能让它错、那种样本在不在这批里**。

## 诚实边界

单项目、单日、同一并行协作批次(四方)。七次实例的失效模式互不相同、且**没有一次读数可疑**——这正是促升理由:这族失败没有事后指纹,只能靠事前明写的问题清单兜(同 `reporting-limits-and-null-results.md` 的促升逻辑:有明确机制 + 可量化代价、且自查抓不到的失败,越早写下越省)。未跨项目 / 跨团队验证 ⇒ apply-and-refine。
