# 交付文档的表达

本 skill 应用项目文体规范，并提供表达方法。它不自行增加审批、图示、术语表或文档发布步骤。

## 规范来源

散文语言、技术标识符和数量表达遵循规范库 `guidelines/writing/prose-and-register.md`；文档归属和同步遵循 `guidelines/workflow/documentation.md`。只在当前写作问题涉及相应规则时读取，已有上下文可复用。规范库根从消费项目的接入指针定位，不把安装目录当作规范库根。

用户指定的文体、模板和交付格式优先于这里的方法建议。引用技术资料不自动启动代码实现或其他工作流。

## 当前任务怎么做

| 当前需要 | 输入与动作 | 产出与检查 |
|---|---|---|
| 起草正文 | 明确读者、使用目的、已确认事实和待定事项 | 读者能据此作决定或执行操作；技术标识符可查找 |
| 解释陌生术语 | 首次出现处解释；术语多且反复使用时可集中列表 | 不要求每份文档都加开篇术语表 |
| 表达流程或比较 | 选择文字、列表、表格或图，取最易理解的形式 | 不因超过固定步骤数而强制画图 |
| 使用或修复图示 | 只读 [图示参考](diagram-reference.md) | 在目标渲染器上可读；没有目标验证时说明限制 |
| 修改既有文档 | 保留仍有效的内容与项目风格，检查受影响链接与事实 | 不把局部修改扩成全篇改写 |

## 知识与建议的使用边界

图示类型、术语表和配色是表达方法，不是权限或完成门禁。保留读者所需的操作事实、限制和证据；减少重复说明。发布到外部服务的行为沿用用户授权与实际工具限制，不因“验证渲染”而自动获得发布权限。
