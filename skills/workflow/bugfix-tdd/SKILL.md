# 缺陷修复的证据入口

本技能以修复流程为主。知识说明解释证据为何可信，规范约束结论和授权范围；三者不因放在同一个技能包里就自动成为一套必跑流程。

## 范围

- 用于已经进入修复阶段的缺陷。根因仍不清楚时先调查，不用猜测的修复替代诊断。
- 审查中发现的缺陷，只有已属于授权修复范围时才进入修复；范围外问题先报告。
- 沿用用户选择的审批方式和已有授权。选择测试形式、记录红测案本身不新增审批点。
- 不自动加载其他 TDD、调试、fixture 或收尾技能；当前问题确实需要另一项能力时才独立选择。

## 证据和授权边界

1. 修复前实际运行复现，确认失败来自目标缺陷；修复后对相同输入和判据再次运行。已有可靠的修复前证据可复用，写清对应的版本、输入与环境。
2. 自动测试和可复现的交互验证都可以提供证据。agent 能操作并可靠观察时自行验证；只有需要人的判断或缺少访问权限时才请用户参与。
3. 回归覆盖受影响的行为、调用方和项目要求的检查。共享接口或影响面不明时扩大检查，不默认跑任意仓库的全部测试。
4. 不以静默跳过失败测试、只看退出码或只读代码代替验证。无法获得所需证据时，说明未验证部分及原因，不宣称修复已验证。
5. 修复与对应测试、fixture、必要说明应保持可一起审查和应用。已有提交授权且适合单一主题时一起提交；本技能不授予提交权限，也不强制制造提交。
