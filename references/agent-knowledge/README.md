# Agent 知识组织：检索、综合与执行怎样分工

本页用于选择知识组织方式，属于带来源的解释与比较。它不增加审批、自动任务或全局加载规则。内容分类与权限以[内容边界](../../guidelines/workflow/instruction-content.md)为准，维护办法以[知识促升与维护](../../guidelines/workflow/knowledge-promotion.md)为准。

> 资料状态：概念说明依据下列原始资料；本仓采用顺序来自 2026-10-13 用户确认的轻量知识管理方案。没有运行 RAG 或 Wiki 的模型 A/B 实验，不承诺降低 token、耗时或错误率。

## 四种能力解决不同问题

| 能力 | 负责什么 | 不能据此认定什么 |
|---|---|---|
| 知识管理 | 保存来源，区分事实、假设、版本与核验状态，处理更新和失效 | 写进仓库不等于已验证 |
| RAG（检索增强生成） | 在回答时寻找相关材料，供模型据此作答；可组合关键词和语义检索 | 搜索相似度不决定规范权限，也不证明材料正确 |
| LLM Wiki | 由模型维护有来源、互相链接的主题或比较页，复用跨资料的理解 | 自动整理不等于自动裁定冲突；综合页不能自我证明 |
| 工作流引擎，例如 Loom | 保存执行阶段，检查已定义的继续条件，支持等待与恢复 | 满足结果字段条件不单独证明外部动作真实发生 |

RAG 与 Wiki 可以组合：先维护主题页，再检索主题页和必要的原始证据。采用哪种方式取决于查询和维护成本，不以文件数量直接决定。

需要约束实际改动时，见[范围审查与执行入口](scope-control.md)：比较独立审查、Git 集成入口与 Loom 的职责、绕过边界和试点判据。这是机制评估资料，不是默认安装或审批要求。

## 用同一个问题理解区别

问题：“UE 设置重启后丢失，同事也看不到。”

检索会找到 [UE 配置资料](../../skills/ue/ue-settings-persistence/SKILL.md)。综合页可以解释用户配置与项目共享配置的目标差异，并指回实际做法。知识管理负责说明证据来自哪个项目、哪些版本未记录、当前目标版本还需核对什么。若修复需要跨会话执行，工作流才负责记录复现、修复与验证阶段。

这几项能力可以分别采用。一个索引和几份良好维护的 Markdown 已经能提供知识组织价值，无须同时部署数据库、网页产品或流程引擎。

## 本仓的采用顺序

1. 使用现有 Markdown、Git、主题索引与按需搜索，修复旧链接及摘要与主来源的冲突。
2. 给易变或存疑结论补必要的适用范围和证据。未记录的版本保持未知，不用整理日期冒充验证日期。
3. 仅为反复出现的跨资料问题保留综合页。本页与[问题导航](find-relevant-guidance.md)是当前的小范围应用，不按每篇文章自动扩页。
4. 若真实问题仍反复漏找或需要大量重复阅读，再比较检索方案。使用[固定案例与判据](../../docs/evaluations/knowledge-retrieval.md)，分别记录正确性、读取量和维护成本。

2026-10-13 用户进一步同意在知识部分做单主题试验：[UE 渲染 Wiki](../ue-rendering/wiki-pilot/README.md)保存跨文档综合，并演练来源变化后的人工辅助更新。这是局部维护试点，尚未采用全库自动整理或自动知识促升。

根入口保留必要的任务边界。具体规范按当前行为明确定位，领域知识按问题检索；搜索命中不是唯一的规范加载依据。宿主注入的技能名称、描述与工具说明是另一类上下文成本，增加检索服务不会自动移除它们。

## 何时值得增加检索或综合能力

| 反复出现的现象 | 先尝试什么 |
|---|---|
| 中文症状与英文术语不匹配 | 补问题索引与少量别名，允许查询改写 |
| 来源找到了，但总要重复阅读多份文档才能理解 | 保存一份带来源的主题比较，记录仍有分歧的条件 |
| 已知路径或精确 API 名仍找不到 | 先查路径、索引和关键词搜索，不让语义结果盖过精确名称 |
| 多目录资料持续漏找，索引与关键词已不能满足任务 | 比较带版本、来源和核验状态的混合检索 |
| 旧资料和新资料说法冲突 | 回到证据及适用范围裁决；换检索器不能直接解决 |
| 任务经常中断后漏步骤 | 评估任务记录或窄流程状态管理，不把执行状态当知识页内容 |

## 来源与复核方法

- [RAG 原始论文](https://arxiv.org/abs/2005.11401)：检索证据与生成的组合。现代检索实现的选择不只限于原论文架构。
- [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)：关键词、语义检索及片段上下文的作用；其产品实验结果不外推为本仓收益。
- [LLM Wiki 原始说明](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：维护关联 Markdown 的模式，不是指定产品或本仓行为规范。
- [按需上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：使用路径、搜索及逐步读取组织上下文。
- [Loom 执行职责](https://github.com/waynebaby/Techne-Loom/blob/main/docs/en/guides/so-guide-reference-behavior.md)：本地确定性步骤与外部步骤的分工。版本变化时应重新核对工具行为。
