## 候选

### 1. Claude Code auto-mode / sandbox 三连硬化(2026 年 6 月,`[3-0 已核验]`)
- **是什么**:6 月三个版本给 auto mode + sandbox 加了 harness 级硬约束:
  - `2.1.183`(06-19):auto mode **拦截未经要求的破坏性命令**——`git reset --hard` / `git checkout -- .` / `git clean -fd` / `git stash drop`;`git commit --amend` 若该 commit 不是本 session agent 建的也拦;`terraform/pulumi/cdk destroy` 除非点名具体 stack 否则拦。
  - `2.1.187`(06-23):新增 `sandbox.credentials` settings——**阻止 sandbox 命令读凭据文件 / secret env**。
  - `2.1.193`(06-25):新增 `autoMode.classifyAllShell`——把**所有** Bash/PowerShell 走 auto-mode classifier(不再只拦「任意代码执行」模式)。
- **为什么可能跟你相关**:直接撞你已有的两块——`techniques/claude-code-autonomous-permissions.md`(手动改 settings.json 放开 commit 的那套)现在有了**引擎侧的对称防线**:即便放开了权限,auto mode 仍会拦 destructive git。`guidelines/workflow/agent-lifecycle.md` 的「Do not use destructive actions as shortcuts / 别用 `reset --hard` 当捷径」原来是**靠 agent 自律**,现在 Claude Code 把它**变成 harness 强制**了。可能给 autonomous-permissions technique 补一节「引擎侧 auto-mode 现在替你兜了哪些 destructive 命令 + `sandbox.credentials` 给 CI 凭据隔离的新 knob」。
- **促成门槛**:核对这三个 settings key 的准确拼写 + 默认值(尤其 `autoMode.classifyAllShell` 是否默认开)。跟 autonomous-permissions.md 现有的「ask/allow/deny + precedence」不冲突,是**新增的 auto-mode 层**(不同于 permissions 三 list),要说清两者关系别混淆。
- **来源**:https://code.claude.com/docs/en/changelog

### 3. Claude Code 压缩时按 LRU 驱逐已调用 skill(`[3-0 已核验]`)
- **是什么**:compaction 时 Claude Code 按**总预算**重新注入已调用的 skill,超预算**先丢最早调用的**(LRU)。长 session 调了很多 skill 后,一次压缩会**静默丢掉最早那几个** skill 的正文。
- **为什么可能跟你相关**:你 repo 里 skill 已经很多(workflow / ue / maya / architecture / collaboration),长对话跑 supervised/autonomous workflow 时会连调多个 skill。这条是「skill 不是调了就永久在 context」的具体 hidden contract,跟 `techniques/context-budget-audit.md` 的「加载时机三档模型」正交补一格——「被调才进」那档还有个**压缩后会被 LRU 踢出**的隐藏行为。可能给 context-budget-audit 补一行,或作为 multi-session/长对话的注意事项。
- **促成门槛**:确认这是否随版本变(blog 描述的行为可能已迭代);判断它是「值得写进 guideline 的稳定契约」还是「版本相关、易过时」。属 awareness,门槛偏高。
- **来源**:https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more
