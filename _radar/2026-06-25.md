- **来源**:https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more

### 4. GitHub Spec-Kit / Spec-Driven Development —— 外部成型方法论
- **是什么**:GitHub 官方维护、MIT 开源的 spec-driven 开发工具包。把 spec 当**可执行产物**(多步精化生成实现,非一次性 codegen),给出具体 slash-command 流水线:`constitution / specify / clarify / plan / tasks / implement`。
- **为什么相关**:跟你的 `skills/workflow/supervised-workflow` + `autonomous-workflow` + superpowers `writing-plans` 是**同生态的外部参照系**。值得对比:它的 phase 边界 vs 你的 gate 模型,有没有可借鉴的(如 `constitution`=项目宪法、`clarify` 阶段)。
- **促成门槛**:它是**方法论 + 工具**,不是单条规则。促成方式应是「评估后把可借鉴点 adapt 进现有 workflow skill」,而非整包搬入。先读一遍 repo 再判断。
- **来源**:https://github.com/github/spec-kit

### 5. Context engineering 作为独立学科:JIT 检索 + agentic 笔记(Anthropic 工程博客)
- **是什么**:Anthropic 把 "context engineering" 定义为高于 prompt engineering 的学科——每个推理周期**策展整个 token 集**。两个可操作技术:**just-in-time 检索**(存轻量引用/路径,运行时按需拉,不预载)+ **结构化笔记 / agentic memory**(把笔记落盘到 context 外,需要时再拉回,跨 context reset 保持连贯)。
- **为什么相关**:JIT 检索 = 你 `coordination-patterns.md` 的「iterative retrieval」的官方背书 + 更一般的框架;agentic memory 跟你的 `~/.claude/.../memory/` + daily/open-items 机制同构。可强化 context-budget-audit.md / coordination-patterns.md 的「为什么」论证。
- **促成门槛**:部分已被你覆盖(iterative retrieval / memory)。促成价值在于**引一手权威 framing**,不是全新规则。
- **来源**:https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents

### 6. Multi-agent 经济学 + LLM-as-judge 评测法(Anthropic multi-agent 博客)
- **是什么**:两条可量化结论——multi-agent 约耗 **15× tokens**(单 agent ~4×),是「值不值得上 multi-agent」的核心成本约束;**token 用量单独解释研究任务质量 80% 方差**。另:最稳的 agent 输出评测是 **单次 LLM-as-judge + 一个 rubric**(0.0-1.0 分 + pass/fail,维度:事实准确/引用准确/完整性/源质量/工具效率)。
- **为什么相关**:成本框架可补进 `coordination-patterns.md`(你那篇讲了 when-to-parallelize 但没成本量纲);LLM-as-judge rubric 是 `techniques/adversarial-verification.md` 可落地的一个具体评测形态。**本轮的 8M-token / 撞额度事件本身就是这条的活教材**。
- **促成门槛**:⚠️verify 数字(15× / 80%);rubric 思路可直接借鉴。
- **来源**:https://www.anthropic.com/engineering/multi-agent-research-system
